# 🗺️ Кластеризация мест на карте и оптимальный маршрут

Программа для работы с местами на карте:

1. **Поиск мест** — через OpenStreetMap (Nominatim + Overpass API), без API-ключей;
   также импорт из CSV/JSON и ручной ввод координат.
2. **Кластеризация по плотности** — DBSCAN / HDBSCAN на метрике haversine:
   места, расположенные густо относительно друг друга, объединяются в кластеры;
   одиночные точки помечаются как «шум».
3. **Оптимальный маршрут** — TSP-оптимизация двух уровней:
   - `по кластерам`: сначала оптимальный порядок посещения кластеров (по их центроидам),
     затем оптимальный обход мест внутри каждого кластера (с учётом точки «въезда»);
   - `по всем местам`: единый сквозной оптимальный маршрут.
   Точное решение (branch & bound) для малых наборов ≤ 9 точек, иначе —
   nearest-neighbor + 2-opt. Поддержка старта/финиша (depot) и вставки шумовых
   точек cheapest-insertion.
4. **Интерактивная карта** (folium): маркеры, окрашенные по кластерам, овалы охвата,
   центры кластеров, линия маршрута с нумерованными остановками, легенда, слои.

## Структура проекта

| Файл | Назначение |
|---|---|
| `places.py` | Модель `Place`, поиск: геокодирование (Nominatim) и категории (Overpass) |
| `geo_utils.py` | Haversine, матрица расстояний, центроид сферы, парсинг координат |
| `clustering.py` | `cluster_places()` — DBSCAN/HDBSCAN по плотности + оценка silhouette |
| `routing.py` | `plan_route()` — TSP по местам и двухуровневая оптимизация по кластерам |
| `visualization.py` | `render_map()` — интерактивная HTML-карта |
| `cli.py` | Консольный интерфейс полного цикла |
| `app.py` | Веб-интерфейс (Streamlit) |
| `test_core.py` | Юнит-тесты ядра (работают офлайн) |

## Запуск

### CLI

```bash
# демо-набор достопримечательностей Санкт-Петербурга
python cli.py --demo --eps 500 --min-samples 3 --mode clusters \
              --depot "59.9385,30.3370" --out map.html

# найти все кафе в Казани (радиус ~4 км от центра), кластеризовать, построить маршрут
python cli.py --category "Кафе и рестораны" --city "Казань" --radius-km 4 \
              --limit 60 --eps 500 --mode clusters --out cafe_kazan.html

# текстовый запрос + маршрут по всем местам сразу
python cli.py --query "музеи, Санкт-Петербург" --city "Санкт-Петербург" \
              --mode places --out museums.html

# свои места из файла (CSV: name,lat,lon[,category,address] или JSON)
python cli.py --places-file my_places.csv --eps 300 --out my_map.html
```

Параметры кластеризации:
- `--eps` — радиус окрестности, м: места в пределах этого расстояния считаются «соседями»;
- `--min-samples` — минимум мест в окрестности, чтобы точка стала «ядром» кластера;
- `--method dbscan|hdbscan` — HDBSCAN сам подбирает плотность (при отсутствии пакета
  выполняется DBSCAN с адаптивным eps по k-distance графику).

streamlit run app.py

## Как это работает

### Кластеризация по плотности
Строится матрица попарных расстояний haversine (метры), затем DBSCAN на
`metric="precomputed"` связывает в один кластер цепочки близко расположенных мест.
В результате получаются `clusters` (со списком мест, центроидом и радиусом) и
`noise` — редкие точки вне плотных областей.

### Маршрут по кластерам (двухуровневый TSP)
1. Порядок кластеров = решение TSP на их центроидах (старт — ближайший к depot).
2. Внутри каждого кластера маршрут стартует от точки, ближайшей к предыдущему
   кластеру («точка въезда»), и оптимизируется отдельно.
3. Шумовые точки вставляются cheapest-insertion в наиболее дешёвые позиции.
4. Опционально замкнутый контур через depot (старт = финиш).

Для n ≤ 9 применяется точный branch & bound, больше — жадный nearest-neighbor
с улучшением 2-opt. Итог: длина всего маршрута, разбивка «внутри кластеров /
межкластерные переезды», поименованный список остановок.

## Ограничения

- Nominatim/Overpass — публичные сервисы OSM: соблюдайте rate-limit (1 запрос/сек),
  для продакшена подключите свой геокодер/OSRM для реальных дорожных расстояний
  (здесь используется ортодромия — расстояние «по прямой»).
- TSP — NP-полная задача; эвристики дают близкое к оптимальному решение, но не гарантируют глобальный оптимум на больших наборах.
